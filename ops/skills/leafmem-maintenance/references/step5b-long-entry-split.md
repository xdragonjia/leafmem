## 1. 覆盖度扫描：外置还是索引指向

### 1.0 🔴 先判「该不该拆」（2026-10-20 补，防对同一批合法长文每周重复分析）

- `weekly_scan.py` 的 flag：`合法长文`（content≠summary）＝**长度事实，不是缺陷**；`⚠️畸形(content==summary)` 才是缺陷，优先修。
- **该拆**：① ≥5,500 字符（余量 <10%，任何追加都撞 6,000 上限）；② 一题多族的**合并磁石**（同一条并存多个可独立检索的主题/谱系）。
- **不该拆**：单主题长文（一条 principle 一个判据 + 其展开）、**过时 runbook 型**（内容已被现行技能文档取代，如旧版升级指南 v0.6.x、已退役工具 mmx-cli 的 SOP）——后者加 `已被替代 by <技能/版本>` 标注，走步骤 8 降权；拆开只会把过时细节分散成更多条。
- **2026-10-20 基线（判定保留，不拆）**：`8997d15f`5318 / `74755790`5168 / `16a0f0bd`5100 / `4eb98204`4502 / `d3029eab`4404 / `243e13cb`4393 / `d4143f85`4332 —— 均为 `合法长文`。后续以「基线外是否出现新条目」为唯一判据，基线内不再逐周说明。
- **已知待降权项**（非拆分）：`74755790`（WeKnora v0.6.1→v0.6.3 升级指南，现行 SOP 在 weknora-rag 技能 v3.6/v0.8.0）、`d3029eab`（mmx-cli 配图 SOP，已由 image-gen v1.11.0 收编且 mmx/豆包通道退役）。

🔴 拆分**前**必须先做覆盖度扫描，判定「每个语义段是否已被兄弟条目承载」，再决定「外置」还是「索引指向」。

- **方法**：为原文每个语义段取 1–2 个**特征串**，全库执行
  `SELECT id FROM memory_items WHERE content LIKE '%串%'`。
- **判定**：
  - 命中集合**只含本条** ⇒ 磁石独有 ⇒ **必须外置**。
  - 命中**含他人** ⇒ 索引指向既有 id ⇒ **不复制**（复制＝制造重复）。

## 2. 执行序列（有序）

1. **前置**：跑覆盖度扫描（见 §1）。
2. **外置**：`remember` 新建原子条目，`--metadata` 带
   `{"projectId":"proj_local_mql2p6a1","family":"<族名>","parentId":"<父完整UUID>"}`；
   标题含族名 + 证据日期。
   🔴 `parentId` 必须取**完整 36 位 UUID**（`leafmem-cli get` 或只读 sqlite 查得），**禁用 8 位短前缀** —— 2026-10-11 首跑写错一组（记成 `62d1`，真值 `c6d1`，仅一字之差），与步骤 6 的 supports 短 id 事故同源。
3. **核验**：`remember` 之后**立刻** `get` 核 `createdAt` 为**当日**。早于今日 ⇒ 命中并覆盖了既有条目，须立即按步骤 3 存档恢复原文。
4. **父条目回写**：用 `leafmem-cli update` 传「完整父 UUID」并指定 `--content`（核心 + 谱系索引）与 `--summary`（新摘要）。
   - 🔴 **不传 `--metadata`**（PATCH 为替换语义，传了会波及 `recallCount` / `lastRecalledAt`）。
   - `--tags` 传**原 tags 的并集**。
   - 父条目保留族规：「本族新教训一律 kind=lesson 另立原子条目互引 id」。

## 3. 🔴 零丢失硬门禁

🔴 回写后必须对原文**每个语义段的特征串**做**全库** `LIKE` 复扫，`ORPHANS` 必须 **= 0**。

- 出现孤儿 ⇒ 把该细节**回补进对应子条目**后再复验。
- **不得放过、不得只改父条目。**

| 特征串 | 全库命中 |
|---|---|
| `史/理/硬/路` | 0 |
| `歷/處/網` | 0 |

> 🔴 **判据：只查索引池不算取证，必须全库扫描。**
